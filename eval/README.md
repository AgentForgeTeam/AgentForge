# Оценка качества

Здесь всё, чтобы проверить качество Agent Forge и повторить наши цифры:
набор задач, скрипт прогона, проверка ответов и сводка метрик.

## Откуда задачи

Задачи не придуманы командой: они взяты из опубликованных бенчмарков вместе с
эталонными ответами авторов. Выборка детерминирована (зерно 2026), её можно
пересобрать командой `python -m eval.build_dataset`.

| Бенчмарк | Что проверяет | Задач | Как проверяется | Лицензия |
|---|---|---|---|---|
| [FRAMES](https://huggingface.co/datasets/google/frames-benchmark) (Google) | многошаговый поиск: найти и связать несколько статей Википедии | 14 | LLM-судья сравнивает ответ с эталоном по смыслу | Apache-2.0 |
| [GSM8K](https://github.com/openai/grade-school-math) (OpenAI) | текстовые задачи с расчётом | 13 | число в строке `ANSWER:` против эталона | MIT |
| [HumanEval](https://github.com/openai/human-eval) (OpenAI) | функции на Python | 13 | тесты авторов в песочнице | MIT |

Две трети задач проверяются без модели, точно. Треть (FRAMES) нуждается в
судье, потому что «McDonald's в 1940 году» и «McDonald's» - один и тот же ответ.

Файл набора: `data/tasks.jsonl`. У каждой задачи указаны источник, исходный id
и лицензия.

## Что сравнивается

* **Один агент** (`single`): агент подходящей роли получает задачу целиком,
  супервайзера нет.
* **Команда** (`team`): планировщик разбивает задачу на подзадачи с
  зависимостями, их выполняют исследователь, аналитик, разработчик и критик,
  каждый отчёт проверяет супервайзер. Итог - результат последней подзадачи,
  от которой никто не зависит.

Ядро работает так же, как в приложении: оркестратор, инструменты (поиск,
чтение страниц, песочница), бюджет, фильтр prompt injection. Прогон идёт во
временном каталоге данных и не трогает профиль пользователя.

## Метрики

| Метрика | Как считается |
|---|---|
| Успешность | доля задач с верным ответом, с 95% интервалом Уилсона |
| Токены и стоимость на задачу | журнал вызовов `usage_log`, стоимость по таблице `providers/pricing.json` |
| Доля супервайзера | токены проверок и сводок супервайзера к токенам всей задачи |
| Доля планировщика | токены разбиения задачи к токенам всей задачи |
| Выдуманные ссылки | ссылка из ответа не открывается или на странице нет приведённой цитаты (`core/verify/links.py`) |
| Превышение лимита | задачи, где расход оказался больше лимита токенов задачи |
| Цепочка остановлена | прогоны, где подзадача осталась непринятой супервайзером или не запустилась из-за этого |
| Защита от инъекций | доля пойманных атак и ложных срабатываний на открытом наборе атак (`injection_eval.py`) |

## Как повторить

Нужен ключ модели. По умолчанию используется Gemini: агенты на
`gemini-3.5-flash-lite`, супервайзер и планировщик на `gemini-3.1-flash-lite`,
судья на `gemini-3.1-flash-lite-preview`. У каждой модели своя квота, поэтому роли
разнесены: у бесплатных flash-моделей 5 запросов в минуту и около 20 в сутки, у flash-lite запас больше.

```powershell
$env:GEMINI_API_KEY = "ваш ключ"
python -m eval.run --arch single team --out eval/results/my-run
python -m eval.report eval/results/my-run
python -m eval.injection_eval --out eval/results/my-run
```

Прогон можно прервать и запустить снова той же командой: готовые задачи
пропускаются. `--only frames gsm8k` ограничивает набор, `--limit 5` берёт
первые задачи, `--retry-errors` перезапускает задачи, упавшие с ошибкой,
`--agent-model` и другие ключи меняют модели.

Ключ берётся из переменной окружения и никуда не записывается.

Последний замер: `results/kp2/summary.md` (успешность, расход, ссылки) и
